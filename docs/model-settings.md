# DeepSeek 模型设置

在 Wememo 顶部展开“模型设置”，选择 DeepSeek 官方服务地址、填写模型 ID 和 API Key，然后点击“保存到本机并启用”。保存立即应用到关系变化解释和证据追问；它只更新本机配置，不调用模型，也不验证密钥是否具有服务额度。

如果当前应用通过环境变量启动，页面会显示“当前来源：启动环境”。API Key 留空后保存，可以明确地把现用密钥转存为系统加密配置。原来的 `~/.config/wememo/deepseek.env` 不会被自动改写或删除。密钥输入框在提交时清空，应用不回显密钥。

读取顺序是：已保存的本机配置 → 尚无保存文件时使用启动环境。已有配置损坏或无法解密时会报错，不静默切换到环境中的另一把密钥；可以填写新密钥后重新保存。没有安全存储时保存功能不可用，应用不会退化为明文密钥存储。

配置保存在 Electron 用户数据目录的 `model-settings/`：

- `provider.json`：版本、官方服务地址、模型 ID 与随机密钥文件编号。
- `<随机编号>.bin`：系统安全存储加密后的密钥。

目录权限为 `0700`，文件为 `0600`。新密钥先加密写入，配置指针通过重命名切换；切换失败保留原配置，成功后清理旧密钥文件。加密存储依赖操作系统及应用身份，不能将复制密文视为跨机器迁移方式。[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)

保存与模型任务互斥，防止同一次任务中途切换模型。Renderer 只有独立的配置状态与保存接口；关系解释/追问仍只接受范围和问题，不允许提交 Prompt、ContextPack、API 地址或密钥。配置不存入 Renderer localStorage，没有读取密钥的 IPC。

评估 CLI 和独立 Python 实验仍使用各自显式的环境配置，不读取桌面加密存储。

# 失败诊断

关系变化解释和证据追问会继续拒绝不合法结果，同时显示失败阶段：JSON 语法、字段结构、引用范围、引用方向或本地映射。字段诊断只显示约定的字段名；未知属性只统计数量。模型原文、字段值、账号/会话标识、原始证据 ID 和 Provider 原始错误都不用于诊断展示。

没有 JSON 修复、引用补全或自动重试。评估 v2 同时记录首次 JSON 解析、精确字段与引用验证的通过率，未执行的检查仍为 `null`。
